# CLAUDE.md — the repo map

What each file is and what it owns. The README is for people who put komorebi on a page; this file is for people
who work on komorebi. The spec ([`komorebi-spec.md`](komorebi-spec.md)) holds the vision, the physics and the
model. Read the spec before you change what the engine does.

## Files

- **`komorebi.js`** — the engine's public door, an ES module: `export { create, DEFAULTS, … }`, re-exported from the modules below. The whole renderer, no UI.
  - **`komorebi-engine.js`** — `create()` itself: GL plumbing, the shared-internals hub the subsystem factories close over, the rebuild coordinators, auto-quality, and the frame loop.
  - **`komorebi-grove.js`** — `buildGrove`: the grown canopy — trees, leaves binned to depth layers, the woody occluder, the faithful-path geometry; and `placeLeaf`, where one leaf hangs (at its twig's tip or, with `inner_leaves`, on the older wood), which the editor's tree preview calls too.
  - **`komorebi-bake.js`** — the per-frame bakes: leaves to per-layer optical depth, the faithful path's pre-integrated soft shadow, and the sky fill — the hemisphere integral of those layers that lights the shade (`canopy_fill`, §4.7).
  - **`komorebi-fill.js`** — the sky fill's CPU half: the fixed cosine-weighted directions and the per-ray quadrature as pure functions, the reference `fill.test.js` and the pixel harness hold the shader to.
  - **`komorebi-litter.js`** — the fallen leaves as a floor material: the pure laws (where a leaf lands, the one colour law `litterAlbedo`, drop order) and the once-per-regrow RGBA8 carpet bake over the fill's frame.
  - **`komorebi-leaf.js`** — the leaf's outline: the sugar maple grown as a vein skeleton in the plane (`growLeaf`), cut as a radial profile r(θ) from the petiole base and area-normalised (`profile`, `leafShape`), and `leafVariant`, the one hash the grove and the litter share so a fallen leaf keeps its shape — and, with `leaf_variety`, the genotype × light rows (`rowSpec`, `rowBlade`) the outline texture grows to 64. Pure; `GLSL_LEAF_Q` in `komorebi-shaders.js` is its shader half.
  - **`komorebi-source.js`** — the Vogel-spiral point-sun cloud and the shared cast geometry (bulk shift, ellipse projection, layer heights).
  - **`komorebi-motion.js`** — the broadband wind signal and the trunk/limb/twig spring hierarchy.
  - **`komorebi-transitions.js`** — the cloud-bloom crossfade between looks.
  - **`komorebi-render.js`** — one frame onto a target: the transport draw, the per-group uniform upload, the glow tier.
  - **`komorebi-editor-tools.js`** — EDITOR-only: debug overlays, the profiling primitive, the motion mirror.
  - **`komorebi-transport.js`** — the transport master + camera registry: GLSL snippets `buildTransport()` assembles into one program per camera.
  - **`komorebi-shaders.js`** — the bake / faithful-bake / display shaders, the shared tone tail, and the sky fill's bake (`FS_FILL`) with the per-ray snippet (`GLSL_SKY_RAY`) it shares with the sky view.
  - **`komorebi-params.js`** — `DEFAULTS`, the legacy-name migration, the transition key classification, the engine caps, and the feature registry (`FEATURES`, `featuresFor`, `cutWarnings`: which fall tiers a look opens, so a bundle can cut the rest).
  - **`komorebi-math.js`** — CPU math: the atmosphere model, deterministic RNG, wind noise, skeleton-growth helpers.
- **`presets.js`** — the built‑in looks, an ES module: `export const PRESETS` (+ `EXPERIMENTAL`, the looks the editor hides behind its toggle). Split out of the engine (data, not renderer); imported by the pages.
- **`playlists.js`** — EDITOR-only, pure: the editor's playlist model, with no storage and no network but the `fetch` `detect` is handed (and no timer but the one `makePlayer` is handed). Signed out, "all looks" (the built-ins, then the ★ looks) beside the arboretum playlists cached from links. Signed in, the lists are `listChoices`: *uncategorized* (a list derived from the mirror — your presets in none of your playlists, newest first, waiting saves on top; never written to arboretum; hidden when empty and you have other folders), your playlists (the folders), the cached ones from links, *built-ins* (read-only) and *on this browser* (the ★ looks not yet a synced preset); `viewState` joins the mirror's folders and uncategorized to the state for the pure rules below (signed out it returns the state itself, so the mirror shows nowhere). The entries a list shows and steps (`entries`; a ★ that shares a built-in's name has a value of its own, `★ <name>`; `starName` / `entryName` read a value back), whether the active one plays and its times (`plays`, `timing`; uncategorized plays with arboretum's default dwell), the arboretum-origin gate (`detect`: where the session tier is on), the `#arboretum=` / `#arboretum-playlist=` link parser (`parseHash`) and what a link brings in (`fromVersion`, `linkPlaylist`), the play schedule (`makePlayer`), the look equality (`sameLook`, which `builtinTwin` and the chip's "edited" share), the chip under the look select (`lookState`: `built-in`, `★ saved here`, `☁ #id vN`, `⇡ waiting to go up`, `offline copy · <date>`, prefixed `● edited · ` when the live params differ), look provenance (`fromEntry`, `onSaved`/`onDeleted`), the mirror's rules (`emptyMirror`, `mirrorDiff` — which presets to refetch, by version — `mirrorSync`, `mirrorPut`, `mirrorPlaylist`, and the queue of saves that wait: `enqueue`/`dequeue`), moving the ★ looks in (`moveCandidates`, `movePlan`), and the upload and playlist-write plans (`uploadPlan`; `savePlan`: every save signed in, into a folder of yours or else uncategorized; `onlineId`, `placeChange`, `itemsAfter`, `playlistChips`, `isFolder`). `editor.js` drives its preset dropdown, arrow/swipe stepping, save and delete through it; no engine module may import it (design: `editor-integration-design.md` in the arboretum repo).
- **`arboretum-api.js`** — EDITOR-only, network only: `api(origin, fetchImpl, { credentials })`, every call the editor makes to arboretum (health, me, preset by id/version/`k`, your presets, create, new version, playlists, create playlist, put items) over an injectable `fetch`. A session call sends `credentials: 'include'` and the JSON `Content-Type` writes need; a reader (`credentials: 'omit'`) is the anonymous GET a link makes from any origin. A non-2xx answer rejects with `{ status, error, reason, keys }`, a thrown fetch with `{ status: 0, error: 'arboretum unreachable' }`; `commit()` reads `./commit.json` once (null where the site has none). Imported by `arboretum.js` alone (`arboretum-api.test.js` is the wire).
- **`arboretum.js`** — EDITOR-only: **arboretum is the place the editor keeps presets, whether online or not**; the editor only ever saves, loads and lists looks through it, and it does the best it can, in tiers. **Local, always** (storage; no network): `getStored` / `setStored` / `getPreset` (the ★ looks, `komorebi.presets`, over the built-ins), `getState` / `setState` (`komorebi.arboretum`: where each ★ came from, who you were, the playlists cached from links), `getMirror` / `setMirror` (`komorebi.arboretum.mirror`: the offline copy of your cloud — see below; a write the quota refuses keeps the newest presets that fit and marks the copy incomplete, and never drops a waiting save), and the hooks `writeStar` / `deleteStar` that keep a ★ and its provenance together. **Read, from any origin:** `open(link)` GETs an `#arboretum=` / `#arboretum-playlist=` link from `https://arboretum.eljojo.net` with `credentials: 'omit'` when the origin is not a session host, saves it, and says where the editor should land; a browser that blocks it (CORS) or a failing fetch is a failed link, shown quietly through the key-hint line. **Session, only where `detect` says yes** (komorebi.eljojo.net, or arboretum's own dev host) **and you are signed in: arboretum is where your looks live, and signed out it just works locally.** `mount(host)` calls `detect` itself at startup and, if it answers, builds the controls in the advanced panel (`#dev`) and none in the playful sidebar or the zen strip. On each successful `/api/me` check (the advanced panel first shown or a cloud list active, and window focus) it pushes the saves that waited (in order), refreshes the mirror (`GET /api/presets?owner=me` carries versions: only changed presets are fetched, then your playlists) and, once per session, offers to move the ★ looks made before signing in (`moveLocal`: a private preset each, by `uploadPlan`; a refusal stays local with its reason verbatim). `saveCloud` is every save: a new version when the look is a preset of yours, else a new preset (private), into the folder you are in or else uncategorized; when arboretum cannot be reached it waits in the mirror (`⇡`), shown as such, and a session that has ended keeps the look as a ★. Playlists are folders: the `in:` chips toggle membership (so a look leaves or rejoins uncategorized with no request of its own), `create` is the `+`, every items write GETs fresh first and sends the unavailable items back. Offline, every list shows from the mirror and says so. On a fork or `nix run .#dev` `mount` builds nothing and asks the network for nothing (`arboretum.test.js` holds it with a fetch spy). Nothing it sends names `visibility`: everything the editor creates is private. `editor.js` imports it statically and lends it a `host`; no engine module, shim, preset or macro names it, and the built player and embed bundles contain none of it (`arboretum.test.js`). Storage is tested in `arboretum-storage.test.js`.
- **`leaf-maze.js`** — EDITOR-only, pure: the held leaf's physics (spec §4.5, "The held leaf"). `growAreoles` grows the areole maze by successive domain division seeded by the grown veins (`bladeOf`'s skeleton), `rasterLeaf` rasterises it with the walls carrying exactly `wall_fraction`, `paintLeaf` recolours, `tissues` gets τ_wall / τ_cell from `leafTau` itself, `leafMaze` is the memoised leaf at an address. Imported by `leaf-preview.js` only; no engine module, bundle or look may name it (`maze.test.js` holds that).
- **`leaf-preview.js`** — EDITOR-only, DOM: the `L` inset (bottom-left, built on the first press): one grown leaf against the sun with its maze, redrawn only when a signature moves. Imported by `editor.js` alone.
- **`macros.js`** — the control bus: high‑level macros (weather, haze, focus, the wind pad, season, grove, palette, prism), each one input driving an authored multi‑param recipe lifted from the shipped looks. The editor's playful/minimalist modes are its first source; MIDI/audio can drive the same bus later.
- **`index.html`** — the editor / landing page (opens on a welcome screen): three modes — a minimalist auto‑fading strip (the default), a playful macro sidebar, and the full dev panel (`editor.js`'s `PANEL`: eleven collapsible areas grouped by the pass you make — Sun, Colour & light, Density, Season, Leaves, Tree shape, Scene, Wind, Tune, Debug, Lab — each remembering open or closed in `komorebi.editor`'s `open`; the first three start open) — plus HUD, presets, sun‑drag. Imports the modules, so it must be **served** (`nix run .#dev`), not opened off the filesystem.
- **`player.html`** — minimal viewer‑only reference: a full‑bleed canvas cycling through presets, no UI.
- **`examples/`** — the embeds the README points at: a page background, a panel, and the ES-module route. They ship with the site, so they are also the demos.
- **`komorebi.global.js`** — deploy shim: bundles the engine + presets into a classic `window.Komorebi` global for no‑build embeds (the eljojo.net homepage, and anyone else's page).
- **`dev-server.js`** — bun static server + live‑reload for development (`nix run .#dev`).
- **`embed-build.mjs`** — both deploy bundles, so there is one definition of a build. With no arguments (`nix run .#build`) it keeps every shipped look and writes `dist/komorebi.player.min.js`; with look names (`nix run .#embed -- '<look>'...`) it keeps those looks and writes `dist/komorebi.embed.min.js`. It asks the camera registry which cameras the kept looks select and prunes the rest, with their GLSL, uniform groups and per-frame uploads. It asks the feature registry (`FEATURES` / `featuresFor` in `komorebi-params.js`) which fall tiers the kept looks open (the sky fill, the leaf's diffuse share, the autumn pigment, the exposure pass, abscission, the litter carpet) and cuts the rest: the `FEAT_` constants are substituted, the uniform group leaves every camera, and GLSL lines tagged `// @feature <name>` are dropped; `--features a,b|all|none` overrides the set. An orphan sweep then deletes the shader strings nothing references. It also removes the comments from the shader literals and folds the editor tier off. The general player keeps every tier (`montebello` opens all six). The functions are exported and the CLI runs only as the entry script (`bundle.test.js`, `features.test.js`). Check a bundle with `nix run .#embed-check` before you ship it.
- **`glslcheck.mjs`** — offline shader validation: assembles every GLSL template literal in the engine and compiles it with `glslangValidator`, so a shader typo fails here instead of on a black canvas.
- **`test-gl/`** — the pixel harness: real renders of every look in headless Chromium (WebGL2 via SwiftShader) — a PNG per preset under `test-gl/out/`, plus smoke, gate-invariant (byte-identical off states, in pixels), determinism, sky-fill (the shader against its reference; the gate crossed on a running engine) and transition-routing (each tier driven to completion; logic-only) suites. `test-gl/editor.mjs` (`nix run .#editor`) is the editor smoke: it drives index.html's mode ladder + macro bus (and the save prompt, `★` vs built-in of one name, the playlist row / ▶ with a seeded cached playlist, the panel's areas and their remembered state, the look's chip, Ctrl+S, and arboretum's tiers: signed out it is local only (the ★ looks, no request but who you are); at `/index.html` nothing is asked at startup and a `#arboretum=` link is one cookie-less GET to `https://arboretum.eljojo.net` (mocked via `page.route`; blocked, it is said through the hint line); at `/editor/index.html` with `/api/health` mocked the session tier opens, and a whole mocked arboretum drives it: sign-in and the offer to move the ★ looks in, uncategorized and the folders, every save going up (and waiting offline), the offline mirror, the `in:` chips, `+`; then the links and playing, also at `/editor/`: `#arboretum=` with and without `@n&k=`, a failing link, `#arboretum-playlist=` playing and being stopped by an edit, the read-only playlist, and a cached playlist stepping with every call failing) and asserts the observable DOM effects — the UI-only regressions the pixel suites can't see. `test-gl/embed.mjs` (`nix run .#embed-check`) is the embed bundle's proof: it renders each kept look through the embed bundle AND through the raw ES modules in one page and requires the frames to be byte-identical (`--against <bundle.js>` also diffs an older deploy, with a contact sheet). `test-gl/review.mjs` (`nix run .#review -- spec.json`) renders judging frames from a clean export of a commit, lays labelled sheets with quotable IDs and writes the manifest.json the review folders carry. `nix run .#pixels`; first run needs `cd test-gl && npm install && npx playwright install chromium`. PNGs and `node_modules/` stay untracked.
- **`test-gl/render-video.mjs`** (+ `video-lib.mjs`, `video.html`, `gpu-probe.mjs`, `video.test.mjs`) — the video exporter: one look stepped frame by frame into a lossless master and a delivery file, for a projector or a screen rather than a page. It renders in headless Chromium on Metal, so it is the Mac's tool (it fails on any renderer that is not Metal); SwiftShader stays the pixel harness's. N minutes of an arboretum preset for the projector: `nix run .#video -- --arboretum <id> --commit <sha> --out test-gl/out/video/<name> --seconds 300` (`--look-json <file>` for a look on disk; `--help` lists the rest). The defaults that matter: 1080p60; the look as authored (`--set` of `bake_resolution`, `tex_resolution` or `sample_count` keeps it so; any other key is accepted with a warning and the manifest says NOT as authored; `adaptive_motion` and `auto_quality` are refused, being forced off); a 60 Mbit/s HEVC delivery (`-b:v 60M -maxrate 75M`, about 2 GB for five minutes) that plays from a FAT32 stick, with a warning before the render and after the encode when it may pass the 4 GiB; the lossless segments are the master and are kept (`seg/`); resumable: the same command again continues from the last checkpoint, and refuses, naming what moved, if the engine, the look (an arboretum preset's version and params), the exporter, macOS or Chromium changed.
  - **`render-video.mjs`** — the driver: arguments, the run key, the render loop and its retries, the delivery, the stills, `--measure`, the manifest.
  - **`video-lib.mjs`** — the shared half: the filter chains and ffmpeg commands as strings, the static server, Chromium's launch, the arboretum client, the bitrate, FAT32 and disk arithmetic.
  - **`video.html`** — the page: a clock the driver pumps one frame at a time, the engine at render size, the read-back and the POST.
  - **`gpu-probe.mjs`** — does Metal come up headless, are its pixels repeatable, what does a frame cost; run it before trusting a new machine.
  - **`video.test.mjs`** — `nix shell nixpkgs#nodejs_22 nixpkgs#ffmpeg -c node --test test-gl/video.test.mjs`: needs git on PATH and `cd test-gl && npm install` (the exporter imports playwright; no Chromium is downloaded or started). The downscale, the delivery's frame pairing, the run key and its refusals, the arboretum client against a mock that answers the server's own shapes.
- **`.github/workflows/pages.yml`** — the deploy: builds `dist/` and publishes the repo to GitHub Pages (komorebi.eljojo.net) on a push to `main`, writing `commit.json` (`$GITHUB_SHA`) into the site for the editor's uploads; a local checkout has none. The bundle is there to download; the README tells embedders to serve their own copy.
- **`komorebi-spec.md`** — the living spec (vision, physics, model). Kept in sync as the engine evolves.

## Arboretum

"Arboretum" is the place presets are kept, whether online or not: the editor only ever saves, loads and lists looks through `arboretum.js`, and arboretum does the best it can. Signed out, or on a host with no session, it works locally without a problem: the ★ looks (and the record of where each came from) live in this browser's localStorage on every host. The cloud is as far as the browser allows, in tiers: **read** from any origin (a link you open is fetched anonymously from `https://arboretum.eljojo.net`; if the browser blocks it, the editor says so quietly and carries on), and the **session** (sign-in, your presets and playlists, uploads, chips) only where `detect` (`playlists.js`) answers yes: komorebi.eljojo.net, and arboretum's own dev host. Signed in, arboretum is where your looks live and a full copy of them is kept in this browser (the mirror) for when arboretum cannot be reached; playlists are folders, and "uncategorized" is a list the editor derives from the mirror, never written to arboretum. On a fork, GitHub Pages under another host or `nix run .#dev` here, `detect` answers null without a request, arboretum turns its session half off and nothing is asked of the network unless you opened a link. To develop the session half, run arboretum's `nix run .#dev -- <this checkout>` from the arboretum repo and open `https://localhost:8787/editor/`, where its dev server serves this editor on its own origin. `nix run .#dev` in this repo has no session.
